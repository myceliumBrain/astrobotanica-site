Cole um token de acesso pessoal do GitHub (fine-grained, restrito ao repositório astrobotanica-site, com permissão Contents: Read and write — crie em github.com/settings/personal-access-tokens/new) e escolha uma senha. O token fica criptografado (AES-GCM, chave derivada da sua senha via PBKDF2) e salvo em data/auth.json, no próprio repositório — nunca em texto puro.

Acessos

Cada acesso é um token do GitHub próprio, criptografado com a senha de quem vai usá-lo. Revogar aqui remove o registro do data/auth.json — se o token vazou de verdade, revogue também no GitHub (Settings → Developer settings → tokens).

Admin vê o painel inteiro; colaborador vê a seção "Conteúdo" e "Integrantes" — nesta, só pode editar ou remover os integrantes que ele mesmo adicionou. A restrição é do painel: o token do GitHub de um colaborador continua podendo alterar qualquer arquivo do repositório direto pelo GitHub.

Cada acesso fica ligado a um integrante (a pessoa em "Integrantes"). É assim que o painel sabe quem é o autor dos textos de cada acesso.

Adicionar novo acesso

Quem é essa pessoa em "Integrantes" — define a autoria dos textos dela. Cadastre o integrante antes, se ainda não existir.
